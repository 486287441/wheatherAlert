# M03-通知去重与历史持久化

技术依据：见 `plan/技术方案.md`。

## 模块目标

确保“同一城市同一天只通知一次”，并把通知与错误提醒写入可查询历史。

## 实现范围

1. 初始化 SQLite 表结构：`rain_notification_state`、`notification_history`、`app_state`
2. 实现去重仓储：
   - 查询 `(city_code, target_date)` 是否已通知
   - 成功发送后写入唯一记录
3. 写入历史记录（雨天提醒 / 拉取失败提醒）
4. 提供“查看历史通知”查询接口（按时间倒序）

## 关键产物

- `NotificationStateRepository`
- `NotificationHistoryRepository`
- 数据迁移脚本（初版 schema）

## 验收标准

- 同一城市同一目标日期不会重复插入通知状态
- 应用重启后去重仍生效
- 可读取最近 N 条历史通知供托盘菜单调用
