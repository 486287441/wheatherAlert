# Windows 天气降雨提醒 — 技术方案

基于 `需求.md` 的已定决策，本期目标是交付一个 Windows 后台常驻提醒工具：每小时拉取天气，识别今天/明天降雨，按“同一天仅一次”规则发送 Toast 通知，并支持托盘菜单的三项操作（立即检查、查看历史通知、切换城市）。

## 1. 技术选型结论

- **语言与运行时**：`C# + .NET 8`（与原始需求一致，Windows 集成能力好）
- **应用形态**：`Worker Service + Tray Host`（后台常驻 + 托盘交互）
- **天气接口**：和风天气逐小时 API（未来 24-48h）
- **通知能力**：Windows Toast（`Microsoft.Toolkit.Uwp.Notifications` / WinRT 通知 API）
- **本地存储**：`SQLite`（用于通知去重、历史记录、当前城市、运行状态）
- **重试策略**：`Polly` 指数退避重试（失败后最多 3 次）

选型理由：
- PRD 要求“后台静默、可靠、可持久化、可查历史”，SQLite 比 JSON 更适合可查询历史与后续扩展。
- PRD 明确需要托盘菜单与城市切换，单纯控制台程序不够，采用托盘宿主更稳妥。

## 3. 运行与部署

- **本地运行**：`dotnet run --project src/WeatherAlert.App`
- **后台常驻**：默认最小化到托盘，不弹主窗口
- **开机启动**：通过注册表 `Run` 项（可在配置中开关）
- **日志**：结构化日志写入本地文件（按日滚动）
- **发布**：`dotnet publish -c Release -r win-x64 --self-contained false`

## 4. 数据流

1. 定时器每小时触发 `CheckWeatherUseCase`
2. 调用和风 API 拉取当前城市未来 48 小时逐小时数据
3. 提取“今天/明天”的下雨时段与强度概览
4. 查询 SQLite 去重表：目标日期是否已通知
5. 未通知则发送 Toast（文案仅“时段 + 强度”，不带建议）
6. 写入通知记录与历史表
7. 若接口失败：重试；连续失败后发一次失败提醒

## 5. 数据模型（SQLite）

- `app_state`
  - `key` (PK), `value`, `updated_at`
  - 用于保存当前城市、最近失败提示时间等
- `rain_notification_state`
  - `city_code`, `target_date`, `notified_at`, `message_hash`
  - 唯一键：`(city_code, target_date)`，保证同城同日期只通知一次
- `notification_history`
  - `id`, `created_at`, `type`(rain|error), `city_code`, `title`, `body`, `meta_json`
  - 用于“查看历史通知”

## 6. 与 PRD 对应表

| PRD 决策 | 实现要点 |
| --- | --- |
| 任意降雨即提醒（`any_rain`） | 降雨判定阈值设为“有降雨信号即命中” |
| 全天提醒（`all_day`） | 不做静默时段过滤 |
| 文案“时段+强度，不要建议” | Toast 文案模板固定两段：日期/时段 + 强度 |
| 失败自动重试并失败告警 | 每轮最多 3 次重试；连续失败发一次 error Toast |
| 可切换单个当前城市 | 托盘菜单提供“切换城市”，落库到 `app_state` |
| 托盘三菜单（立即检查/历史/切换城市） | 托盘右键菜单固定三项，历史窗口读取 `notification_history` |

## 7. 测试与验收策略

- 单元测试：降雨判定、去重逻辑、重试触发条件
- 集成测试：SQLite 读写、API 响应解析
- 手工验收：模拟今天/明天有雨与无雨、跨天后再次提醒、网络异常与恢复
