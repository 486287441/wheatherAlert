01 · Executive Summary

执行摘要

WeatherAlert 是一款运行在 Windows 系统托盘上的降雨提醒应用：按可配置间隔拉取和风天气 24 小时预报，判断「今天」与「明天」是否可能出现降雨，并以托盘图标、气泡通知与本地历史记录三种方式反馈给用户。项目采用四层解决方案结构，核心业务与 UI 解耦，38 项单元测试全部通过。

核心 Takeaways

  • 轻量常驻：默认每 60 分钟轮询一次，无前台窗口占用；托盘右键即可完成检查、查历史、换城市。
  • 去重通知：按「城市 + 日期 + 消息摘要哈希」写入 SQLite，同一自然日不重复记入降雨提醒。
  • 可定位可选手：启动时可用 Windows 定位 + 和风 GeoAPI 解析城市；亦支持全国城市目录手动切换。

02 · Product

产品背景与目标

通勤与出行前，用户往往只需要一个简单判断：「今明两天要不要带伞？」手机天气 App 信息过载，而系统通知又容易被淹没。WeatherAlert 把答案收敛到托盘一角。

使用场景

典型用户是长期开机的 Windows 办公本用户：应用开机自启后驻留托盘，在降雨来临前数小时通过图标与历史记录获得可回顾的提醒，而不必反复打开完整天气界面。

功能一览

能力 行为说明 入口
定时检查 后台 WeatherWorker 按 PollingMinutes 拉取 24h 预报并更新托盘图标 自动
立即检查 同步执行一次完整检查，并通过气泡展示今/明降雨摘要 托盘右键 · 立即检查
图标状态 今或明有雨 → 雨伞图标；否则 → 铃铛图标 托盘区视觉
通知历史 降雨提醒与 API 失败记录写入 SQLite，WPF 窗口分页展示 托盘右键 · 历史记录
城市切换 全国城市目录分组选择；或启动时 Geo 定位解析 托盘右键 · 切换城市
毛玻璃飞层 自绘圆角卡片 + DWM 模糊，点击托盘在屏幕右下角弹出，移开自动收起 托盘左键（M03–M05 模块）
设计取舍：左键不绑定业务弹窗以外的操作，右键承载全部菜单项；降雨「通知」以历史记录 + 托盘气泡为主，而非 Windows Toast 中心，以降低权限与打扰成本。

非目标

当前版本不提供多平台客户端、分钟级雷达、社交分享或账号体系；专注 Windows 10/11 单用户本机场景。

03 · Architecture

系统架构

解决方案 WeatherAlert.TrayPopup.sln 按职责拆为四个项目与一个测试工程，宿主使用 Microsoft.Extensions.Hosting 注册后台服务与依赖注入，UI 与领域逻辑通过接口隔离。

项目组成

项目 职责
WeatherAlert.TrayPopup.App 通用宿主：配置、Serilog、TrayHostedService、WeatherWorker、WeatherChecker
WeatherAlert.TrayPopup.Core 领域模型、仓储接口、RainDetectionService、格式化器
WeatherAlert.TrayPopup.Infrastructure SQLite 仓储、和风 HTTP 客户端、中国城市目录、Windows 定位
WeatherAlert.TrayPopup.Wpf 历史窗口、城市选择对话框、毛玻璃飞层与托盘菜单窗口
WeatherAlert.TrayPopup.Tests 38 项单元/集成测试，覆盖 M01–M06 模块验收点

分层示意

Hosted 服务

应用启动时并行注册以下 IHostedService：

  • SqliteSchemaInitializer：确保库表存在
  • ConfigValidationHostedService：校验 API Key 等必要配置
  • CityLocationBootstrapHostedService：尝试定位并写入当前城市
  • TrayHostedService：创建托盘图标、绑定菜单与 WPF 调度
  • WeatherWorker：定时调用 IWeatherChecker.CheckAsync

模块演进（plan/）

托盘 UI 经 M01–M06 分阶段交付：骨架与测试管线 → 屏幕定位 → 飞层状态机 → 毛玻璃窗口 → 托盘集成 → 全业务迁移。截至 2026-05-29，六项模块验收均为通过。

04 · Implementation

核心实现

一次完整检查由 WeatherChecker 编排：解析城市 → 拉取 24 小时逐小时预报 → 领域层判定今明降雨 → 按规则持久化状态与历史。

检查链路

// WeatherChecker.CheckAsync 简化流程
cityCode = AppState.CurrentCityCode ?? DefaultCityCode;
hourly   = await _weatherApiClient.GetHourlyForecastAsync(cityCode);
result   = _rainDetectionService.Detect(hourly, _clock.Now);
await PersistRainNotificationStateAsync(cityCode, result.Today);
await PersistRainNotificationStateAsync(cityCode, result.Tomorrow);

降雨判定（RainDetectionService）

对「今天」「明天」两个 DateOnly 分别过滤本地时区的逐小时条目。单小时满足 降水量 > 0 或 降水概率 > 0 即视为降雨信号；相邻降雨小时合并为连续时段（间隔超过 1 小时则切段）。强度标签由当日降雨时段内的最大降水量与最大概率推导：

标签 条件（满足其一）
heavy 降水量 ≥ 10 mm 或 概率 ≥ 80%
moderate 降水量 ≥ 2 mm 或 概率 ≥ 40%
light 其余有雨情况

通知去重

仅当 DailyRainSummary.HasRain 为真时写入。仓储先查 HasNotifiedAsync(cityCode, date)；未通知则计算消息体哈希，标记已通知并追加 NotificationHistoryEntry（类型 Rain）。API 连续失败时写入 Error 类型历史，且通过 weather_error_notified 状态键避免刷屏。

城市解析

CityLocationBootstrapHostedService 在启动阶段调用 IDeviceLocationProvider（Windows 定位）与 IGeoApiClient（和风 Geo v2 city lookup），将解析结果写入 AppStateKeys.CurrentCityCode。用户亦可通过 WPF 对话框从 ChinaCityCatalog 内置的全国城市分组列表中覆盖。

手动检查（托盘 · 立即检查）会刷新图标并弹出今/明两条气泡；自动轮询仅更新图标与静默历史，不弹气泡，避免后台打扰。
05 · Operations

使用、配置与运维

本机部署无需数据库服务器；仅需 .NET 10 SDK（开发）或已编译的 Release 输出（运行）以及有效的和风 API 凭证。

环境要求

  • 操作系统：Windows 10 / 11
  • 运行时：.NET 10（net10.0-windows10.0.19041.0）
  • 外部依赖：和风天气 API Key 与专属 API Host

配置 API 密钥

任选其一（勿将真实 Key 提交 Git）：

  1. 复制 appsettings.Local.json.example 为 appsettings.Local.json 并填写 ApiKey、ApiBaseUrl
  2. 环境变量：WEATHER_ALERT_Weather__ApiKey
  3. 仅本机调试时修改 appsettings.json 占位符

启动方式

场景 命令
一键启动（Release 编译） 双击 start.bat 或 .\start.ps1
开发调试 dotnet run --project src/WeatherAlert.TrayPopup.App
立即检查一次 附加参数 --check-now
运行测试 dotnet test WeatherAlert.TrayPopup.sln

本地数据与日志

  • 数据库：data/weather-alert.db（.gitignore，含通知状态与历史）
  • 日志：logs/weather-alert-*.log，Serilog 按日滚动，默认保留 14 天
  • 轮询间隔：Weather:PollingMinutes，代码侧最小钳制为 1 分钟

排障提示

托盘仍为铃铛但预期有雨：先「立即检查」看气泡，再查历史是否已有同日记录（去重导致不再写入）。API 失败：查看日志与历史中 Error 条目，确认 Host 与 Key 是否匹配控制台项目。

06 · Roadmap

结论与演进

WeatherAlert 以最小表面完成「今明降雨」这一单一命题；架构上已为扩展留出清晰边界。

核心结论

  1. 四层拆分使 Core 可独立测试，Infra 可替换天气供应商实现。
  2. 通知去重 + 历史记录兼顾「不骚扰」与「可追责」。
  3. M01–M06 渐进式交付降低了托盘 + WPF 飞层这一高风险 UI 的返工成本。

可考虑的后续方向

  • 开机自启安装项与静默升级通道
  • 可配置的降雨阈值与用户自定义强度规则
  • Windows Toast 与「勿扰时段」策略
  • 多城市监视列表（当前为单城市状态）
快速上手
克隆仓库 → 配置 appsettings.Local.json → 运行 .\start.ps1 → 托盘右键「立即检查」验证链路 → 执行 dotnet test 确认环境一致。
